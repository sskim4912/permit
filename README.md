# PERMIT · 대산 현장 출입관리

Firebase Hosting + Authentication + Cloud Firestore 기반 한국어 출입관리 앱입니다.
대상 프로젝트는 `permit-daesan-461e8`입니다. 공개 배포는 아직 완료되지 않았습니다.

## 사용 방식

- 방문자는 가입·로그인 없이 신청서를 제출합니다. 방문일 달력, 생년월일 힌트, 안전화 230~300mm(5mm 간격), 여러 방문자 입력, 탭 단위 임시 저장을 제공합니다.
- 제출은 최대 10명씩 원자적으로 저장합니다. 제한은 신청서와 공개 요약을 함께 검증하는 Firestore 규칙의 접근 횟수에 맞췄습니다.
- 관리자 화면은 비밀번호만 입력합니다. 내부에서 `sskim07@gsenc.com` 계정으로 이메일/비밀번호 인증을 수행합니다. 비밀번호는 코드에 저장하지 않습니다. Firebase 콘솔에 등록한 비밀번호를 사용하세요.
- 관리자 UID는 `ICEik0y5U3aETq3mvW7sesAsNRB2`입니다. 공통 비밀번호를 아는 사람은 같은 계정으로 관리자 권한을 사용합니다.
- 관리자는 일자별 전체 입력 항목 조회, 수정·삭제, 상태 변경, CSV 다운로드, 수신 이메일 변경이 가능합니다.
- 기본 메일 수신자는 `sskim07@gsenc.com`입니다. 메일 앱을 열고 사용자가 실제로 전송합니다. 서버 자동 발송·승인 자동 확인은 제공하지 않습니다.

## 데이터와 권한

`requests`에는 개인정보를 포함한 신청서를 저장하고 관리자만 읽습니다. `publicRequests`에는 방문일, 요청팀, 방문목적, 상태, 현장 확인자, 버전, 등록시각만 저장합니다. 이 요약은 누구나 읽을 수 있으므로 방문목적에 민감한 정보를 입력하지 마세요. 두 문서는 배치/트랜잭션으로 함께 변경되고 규칙에서도 일관성을 검증합니다. `settings/mail`은 관리자만 조회·변경할 수 있습니다.

기존 콘솔 규칙은 관리자 접근만 허용합니다. 이 앱의 익명 신청을 사용하려면 **저장소의 firestore.rules를 배포**해야 합니다. SDK 설정만으로는 권한이 부여되지 않습니다.

이전 로컬 Python/SQLite 구현의 `server.py`, `data/`는 보존되어 있습니다. Firebase 버전은 해당 DB를 사용하지 않으며 데이터가 자동 이전되지 않습니다.

## 개발 및 검증

Node.js 22 이상과 Python 3를 사용합니다. 에뮬레이터 검증에는 Java 21 이상이 필요합니다.

```sh
npm ci
npm run build
npm run test:ui
npm test
npm start
```

`src/app.js`는 화면, `src/firebase-api.js`는 Firebase 연결이며 `public/app.js`는 빌드 산출물입니다. 직접 산출물을 수정하지 마세요. UI 테스트는 JSDOM 및 API 대역을 사용하므로 실제 Firebase 인증과 규칙을 검증하지 않습니다. `npm test`는 실제 프로젝트 대신 `demo-permit` 에뮬레이터에서 인증·권한·익명 신청·수정·삭제·10명 배치를 검증합니다.

현재 빌드와 UI 테스트 2개는 통과했습니다. 현재 클라우드 환경에서 storage.googleapis.com 다운로드가 차단되어 Firebase 에뮬레이터 검증은 미완료입니다. 배포 전에 `npm test`를 통과시켜야 합니다. 실제 프로젝트 로그인과 배포도 아직 검증되지 않았습니다.
