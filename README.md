# PERMIT · 대산 출입관리

한 화면에서 신청과 관리를 처리하는 Firebase 웹앱입니다. 프로젝트는 `permit-daesan-461e8`, 게시 주소는 https://permit-daesan-461e8.web.app 입니다.

## 사용

- 일반 방문자는 로그인 없이 최대 10명씩 신청합니다. 작성자 이름은 한 번 입력하고, 각 사람의 방문시작일·종료일·목적·요청팀·출입위치를 각각 입력합니다.
- 생년월일·휴대전화는 숫자만 입력해도 하이픈을 자동 삽입합니다. 빈칸·잘못된 날짜·전화번호는 신청 버튼 위 오류와 해당 입력칸 포커스로 안내합니다.
- 작성 중 내용은 자동으로 현재 브라우저 탭의 sessionStorage에 저장하고 새로고침 시 복원합니다. 별도 저장·불러오기 메뉴가 없습니다. 다른 기기와 공유되지 않고 탭을 닫으면 사라집니다. 예전 임시저장 배열도 그대로 복원합니다.
- 신청한 브라우저에서는 본인 신청의 개인정보와 최초 작성자·최근 수정자·수정 시각을 확인합니다. 발주처 전달 전인 승인 대기 신청을 목록 안에서 수정하고, 확인 후 최대 5명씩 선택 삭제할 수 있습니다. 수정·삭제하는 사람의 이름은 한 번 입력해 재사용합니다. 최초 작성자는 변경하지 않습니다. 기존 신청에는 소유 정보가 없으므로 관리자만 처리합니다.
- 관리자 로그인 후 같은 화면에서 전체 개인정보 조회·목록 내 수정·여러 명 선택·발주처 제출·승인 완료·삭제·CSV 다운로드를 사용합니다. 처리자 이름을 입력하고 최대 10명씩 일괄 처리합니다. 삭제 및 승인에는 확인 절차가 있습니다.
- 화면 상태는 **승인 대기 / 승인 완료** 두 가지입니다. 기존 현장 제출·현장 확인·발주처 제출 상태는 데이터에서 지우지 않고 승인 대기로 표시합니다. CSV에 기존 상태값도 포함합니다.
- 발주처 제출은 선택한 인원의 본문과 수신자를 채워 기기 메일 앱을 엽니다. 실제 메일을 전송한 뒤 명시적으로 **전송 완료로 기록**을 누르면 전달 시각을 저장합니다. 메일 작성창을 열기만 해서는 전송 또는 승인 완료로 처리하지 않습니다. 서버 자동 발송 기능은 없습니다.
- 관리자 비밀번호는 Firebase Authentication에서 설정한 값을 사용합니다. 이메일은 화면에서 입력하지 않으며 내부에서 `sskim07@gsenc.com` 계정으로 인증합니다. UID는 `ICEik0y5U3aETq3mvW7sesAsNRB2`입니다. 공통 비밀번호를 아는 사람이 관리자 권한을 공유합니다.
- 수신 주소 초기값은 `sskim07@gsenc.com`이며 목록 아래 **관리 설정 · 다운로드**에서 변경합니다.
- PC 목록은 표, 휴대폰 목록은 카드로 표시합니다. 휴대폰에서는 입력 글자를 16px 이상으로 유지하고 가로 스크롤 없이 표시하며 관리자 일괄 버튼은 아래에 고정합니다. 사용자 수동 확대는 허용합니다.

## 데이터 및 권한

개인정보는 `requests`, 공개 요약은 `publicRequests`, 메일 설정은 `settings/mail`에 저장합니다. 공개 요약에는 방문일·목적·팀·진행 상태·확인자·버전·등록시각만 있습니다. 목적란에는 비밀 정보를 입력하지 마세요. 신청 시 생성한 256비트 난수 키를 해당 출처의 localStorage(`permit-owner-key`)에 보관합니다. 키는 비밀번호와 같은 권한 증표이며 공개 요약·URL·메일·CSV에 포함하지 않습니다. `applicantCopies/{key}/items`는 이 키를 아는 브라우저만 접근하는 본인 신청 사본입니다. 인증된 사용자 신원이나 작성자 이름으로 권한을 부여하지 않습니다. 같은 브라우저 프로필을 공유하는 사람은 본인 신청 권한도 공유하므로 다른 기기·프로필 또는 저장소 삭제 후에는 관리자가 처리합니다. 관리자 및 신청자 수정 시 원본·요약·본인 사본을 함께 갱신하고, 발주처 전달·승인 시 신청자 수정 권한을 서버 규칙으로 차단합니다. 발주처 제출과 승인은 관리자 전용입니다. `requestDeletions`에는 삭제자 이름·시각·최초 작성자·직전 버전을 기록하며 관리자로만 읽을 수 있습니다.

일괄 처리 중 한 건이라도 버전이 다르면 전체 작업이 취소됩니다. 기존 신청서와 로컬 `data/` DB 파일은 삭제하거나 자동 변환하지 않습니다. 이전 Python 서비스 및 Docker 배포 파일은 사용하지 않아 정리했습니다. 로컬 DB는 Firebase로 자동 이전되지 않습니다. 개인정보 보유기간 자동 삭제와 전체 수정 버전별 이력은 아직 없습니다. 최초 작성자와 최근 수정 기록을 보관하며 삭제는 별도 기록을 남깁니다.

## 개발

Node.js 24, Java 21(Firebase 에뮬레이터), 로컬 정적 확인에 Python 3를 사용합니다. 운영은 Firebase Hosting이므로 사용자의 PC 설치가 필요 없습니다.

```sh
npm ci
npm run build
npm run test:ui
npm test
node --test tests/hosting.test.js
npm start
```

`src/app.js`는 화면, `src/firebase-api.js`는 Firebase 데이터 처리, `public/app.js`는 빌드 결과입니다. 빌드 결과를 직접 고치지 마세요. Firebase 테스트는 실제 운영 프로젝트 대신 `demo-permit`에서 실행합니다. 로컬 제한 환경에서는 `FIREBASE_EMULATORS_PATH=/tmp/permit-emulators XDG_CONFIG_HOME=/tmp/permit-config`로 캐시 위치를 지정할 수 있습니다.

## 자동 배포

GitHub Actions가 `permit-firebase-setup` 또는 `main` push에서 빌드·화면 테스트·Firebase 권한/트랜잭션 테스트를 통과한 뒤 Hosting과 Firestore 규칙을 배포합니다. 자격증명은 GitHub repository secret `FIREBASE_SERVICE_ACCOUNT`로만 제공합니다. 비밀키를 저장소나 채팅에 올리지 마세요. 새 버전은 `/deployment.json`의 커밋과 정적 자산을 검사한 뒤 확인합니다. 자세한 연결은 [DEPLOY.md](DEPLOY.md)를 참고하세요.
