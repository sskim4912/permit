## 새 대화에서 첫 확인
1. 실제 작업 경로, git status, 현재 브랜치와 원격을 짧게 확인한다.
2. 적용되는 AGENTS.md를 읽고 기존 변경을 보존한다.
3. permit-firebase-setup의 최신 커밋을 확인한다. 이 문서 이후의 사용자 변경도 있을 수 있다.
4. GitHub 연결과 기존 배포 워크플로 사용 가능 여부를 확인하되, 연결 확인만을 위한 커밋·배포·문자 발송을 하지 않는다.
5. 사용자에게 프로젝트 연결 결과와 실제 필요한 재인증만 짧게 안내한다.

## 배포 및 권한
- .github/workflows/firebase-deploy.yml: Test and deploy Firebase.
- 애플리케이션 브랜치 푸시 → 필수 빌드/테스트 → Firebase Hosting·Firestore rules 배포 → 운영 홈페이지 커밋 확인.
- 기존 GitHub Actions 보안 저장소의 FIREBASE_SERVICE_ACCOUNT를 이용한다. 값을 출력하거나 사용자에게 채팅으로 요청하지 않는다.
- 연결 앱 인증·로컬 Git 자격증명·네트워크 승인·브라우저 로그인·환경 파일은 새 탭이나 새 환경에 자동 승계된다고 보장할 수 없다.
- 기존 자격증명이 유효하면 재사용하고, 실제 인증 실패가 있을 때만 필요한 연결을 안내한다.
- 문서 변경은 [skip ci] 커밋 등으로 사이트 빌드·배포를 생략한다. 정상 기능 변경은 필수 배포 안전장치를 유지한다.
- 문자·메일 발송은 연결 확인 수단으로 사용하지 않는다. 인증정보를 복사하거나 공개 문서에 저장하지 않는다.

## 최근 완료한 기능
- GS건설 원본 로고를 사용한 홈 화면 아이콘과 이름 ‘출입신청’.
- manifest.webmanifest, pwa.js, sw.js 및 Apple 메타데이터. standalone 실행.
- 헤더 로고 오른쪽 ‘홈 화면에 추가’ 버튼. 현재 주황색.
- 지원 Android 브라우저는 beforeinstallprompt로 설치창 호출. 미지원 상태에서는 수동 안내.
- iPhone은 Safari 공유 → 홈 화면에 추가 안내. Safari 자동 실행/자동 설치는 약속하지 않는다.
- standalone 실행에서는 설치 버튼 숨김. 서비스 워커는 신청 데이터나 인증정보를 오프라인 캐시하지 않는다.

## 기존 업무 흐름 보존
- 방문자별 소속 회사명 입력 및 씨텍 엑셀 연계.
- 명단의 차명·안전화 표시, 신청 상세·수정 대화상자 및 관리자 처리자 이름 입력.
- 씨텍 출입예약 다운로드는 첨부 Aurora.xls 원본 양식 기반, 입력 시작 행 A6. 호환 형식을 임의 변경하지 않는다.
- 기존 알림 자동 처리 및 Apps Script 연계는 요청 없으면 변경하지 않는다.
- 주요 파일: src/app.js, public/index.html, public/style.css, public/pwa.js, public/sw.js.
